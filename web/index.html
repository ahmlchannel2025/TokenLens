Agent token economics

TokenLens

Give it an agent run log and it shows where the tokens went: context resent each step against new output, and what compressing at goal boundaries might save.

Try it on real runs · click a card

All five are real HVA runs on Claude Haiku. Compare no compression and compression on (same task, seed 1007) to see the effect.

Bring your own run log →
Claude API agent (your own loop)

Every call already returns token counts. Record one row per step from response.usage and save the array as JSON:

log = []
# inside your agent loop, after each API call:
resp = client.messages.create(...)
log.append({
    "step": i,
    "input_tokens": resp.usage.input_tokens,
    "output_tokens": resp.usage.output_tokens,
    "goal": current_goal,        # optional
    "boundary": is_new_goal,     # optional, marks a goal start
})
# when the run ends:
json.dump(log, open("run_log.json", "w"))

Then give run_log.json to the tool. The goal and boundary fields are optional; with them, the compression estimate can be made.

Claude Code

Claude Code reports per-call tokens through OpenTelemetry (the claude_code.api_request event), not as a file you can drop here. The command-line tool reads that output directly; see the download section below. Its reader for this format is built but not yet checked against a real capture.

Download the command-line tool

The page is for a quick look. To run the analysis over a whole project's logs, including Claude Code's OpenTelemetry output, install the command-line version from the open-source repository on GitHub. It needs Python 3.10 or newer, and nothing else.

The quick way, one command

Installs directly from GitHub without cloning anything:

pip install "git+https://github.com/ahmlchannel2025/TokenLens.git#subdirectory=cli"

Or clone the repository first

Use this if you also want the research code, the paper, and the notebooks:

git clone https://github.com/ahmlchannel2025/TokenLens.git
cd TokenLens/cli
pip install .

Then run it

tokenlens analyze batch_summary.json       # a harness log
tokenlens analyze run_log.json             # a generic step log
tokenlens analyze - < telemetry.jsonl       # Claude Code OpenTelemetry, piped in

The format is detected from the file. Add --json for machine-readable output. The OpenTelemetry reader for Claude Code is built against the documented schema but not yet checked against a real capture.

Two formats are read. One is the harness format, a batch_summary.json or a single run with a steps list carrying tokens_in, tokens_out and tag. The other is a generic step log, a JSON array of {step, input_tokens, output_tokens} objects, with goal and boundary optional, which an agent loop on the Claude API can produce in a few lines.

Generic format example 
[
  {"step":0,"input_tokens":3100,"output_tokens":160,"goal":0,"boundary":false},
  {"step":1,"input_tokens":4200,"output_tokens":240,"goal":0,"boundary":false},
  {"step":2,"input_tokens":7700,"output_tokens":850,"goal":1,"boundary":true}
]

Claude Code reports its per-call token counts through OpenTelemetry, in the claude_code.api_request event, rather than a file. The command-line tool reads that directly.

The compression figure is an estimate from the per-step context curve, not a promise. In the study, compression of this kind cut tokens by about 54% but lowered task success from 20 of 20 runs to 18 of 20, because the agent sometimes stopped early. A saving only counts if success holds, so treat this as the size of the opportunity rather than something to apply as-is.
